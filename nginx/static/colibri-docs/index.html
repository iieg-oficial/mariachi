Inicio rápido

Pega este snippet en cualquier página HTML. El botón flotante aparece de inmediato y al hacer click abre el formulario de reporte. 

<script src="https://iieg.gob.mx/colibri/widget/colibri-widget.v1.js" defer></script>
<colibri-button
  source-app="mi-app"
  api-key="ck_pub_TU_KEY"
  label="Reportar">
</colibri-button>

Reemplaza mi-app por el slug que el equipo IIEG te asignó y ck_pub_TU_KEY por tu API key pública. Si no las tienes, ver cómo obtener una API key.

Funciona en: React, Vue, Astro, Wordpress, Shopify, vanilla HTML, Next.js, sitios estáticos. El widget usa Web Components estándar y Shadow DOM, no contamina los estilos del huésped.

3 modos de visualización

Elige el modo según donde quieras integrar el reporte.

<colibri-button>

Botón redondo (FAB) que se posiciona fixed en una esquina y abre un modal con el formulario al hacer click. Ideal para sitios existentes que quieren agregar reporte sin tocar layout.

<colibri-button
  source-app="mi-app"
  api-key="ck_pub_TU_KEY"
  size="md"
  position="bottom-right"
  label="Reportar"
  icon="bug">
</colibri-button>
Preview

El botón aparece flotante en la esquina inferior derecha.

<colibri-trigger>

Link, ícono, chip o item de menú inline. Click abre el mismo modal que el botón flotante. Útil para footers, párrafos contextuales, o íconos pequeños junto a un dato sospechoso.

<p>
  Si encontraste un problema,
  <colibri-trigger
    source-app="mi-app"
    api-key="ck_pub_TU_KEY"
    as="link"
    label="repórtalo aquí"
    icon="flag">
  </colibri-trigger>.
</p>

Eventos DOM

Los Custom Elements emiten eventos para reaccionar desde el huésped.

btn.addEventListener('colibri:submitted', (e) => {
    console.log('Reporte enviado, id =', e.detail.id);
});

API JavaScript

Identificar al usuario

Adjunta datos del usuario logueado del huésped a todos los reportes posteriores.

window.colibri.identify({
    id: 42,
    email: 'usuario@ejemplo.com',
    name: 'Usuario Test',
    role: 'editor',
    metadata: { plan: 'pro' }
});

Métodos de instancia

// botón flotante
const btn = document.querySelector('colibri-button');
btn.open({ tipo: 'bug' });        // abre con tipo preseleccionado
btn.close();
await btn.report({                // headless: envía sin abrir UI
    tipo: 'sugerencia',
    mensaje: 'Idea X'
});

// form inline
const form = document.querySelector('colibri-form');
form.setTipo('bug');
form.setValues({ url_afectada: location.href });
form.reset();

Cómo obtener una API key

Las API keys se generan desde el panel de administración de Colibri (acceso solo IIEG). El proceso para integradores externos:

  1. Contacta al equipo IIEG indicando el dominio donde se integrará el widget y el tipo de uso (público o server-side).
  2. El admin registra tu app en /colibri/source-apps, configura los dominios permitidos (con wildcards si aplica) y los tipos de reporte habilitados.
  3. El admin genera la API key y te la envía por canal seguro (la key se ve solo una vez al generarla).
  4. Pégala en el atributo api-key del Custom Element y prueba.
Tipos de key: ck_pub_* para integraciones browser (validan CORS estricto). ck_priv_* para integraciones server-to-server (no validan CORS, se usan en variables de entorno).

Patrón estándar para huéspedes React

Si tu huésped es una app React (mapalab, sieej, etc.), el patrón recomendado es un componente ColibriReportButton que envuelve el FAB con el estilo IIEG estándar (fondo blanco, ícono pequeño morado, hover, sombra sutil) y dispara el panel programáticamente vía window.colibri.openPanel. Lo monta una sola vez en el layout global. 

// src/components/ColibriReportButton.jsx
import { useLocation } from 'react-router';
import useAuth from '@context/useAuth';

const SOURCE_APP = import.meta.env.VITE_COLIBRI_SOURCE_APP || 'mi-app';
const API_KEY = import.meta.env.VITE_COLIBRI_API_KEY || '';

const ColibriReportButton = ({ label = 'Reportar problema o sugerencia' }) => {
    const location = useLocation();
    const { user } = useAuth();

    const handleClick = () => {
        if (!window.colibri?.openPanel) return;
        window.colibri.clearContext?.();
        if (user) window.colibri.identify?.({
            id: user.id, email: user.email, name: user.name, role: user.role,
        });
        window.colibri.setContext?.('sourceRoute', location.pathname);
        window.colibri.openPanel({ sourceApp: SOURCE_APP, apiKey: API_KEY });
    };

    return (
        <button
            type="button"
            onClick={handleClick}
            aria-label={label}
            title={label}
            style={{ padding: 0, border: 0 }}
            className="fixed bottom-4 right-4 z-50 w-7 h-7 md:w-6 md:h-6 rounded-full bg-white flex items-center justify-center text-[#6E7477] hover:text-[#8936AB] shadow-[0px_2px_4px_0px_rgba(0,0,0,0.10)] transition-colors"
        >
            <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
                 stroke-linecap="round" stroke-linejoin="round"
                 className="w-3.5 h-3.5 md:w-3 md:h-3" aria-hidden="true">
                <path d="M16 7h.01" />
                <path d="M3.4 18H12a8 8 0 0 0 8-8V7a4 4 0 0 0-7.28-2.3L2 20" />
                <path d="m20 7 2 .5-2 .5" />
                <path d="M10 18v3" />
                <path d="M14 17.75V21" />
                <path d="M7 18a6 6 0 0 0 3.84-10.61" />
            </svg>
        </button>
    );
};

export default ColibriReportButton;

Características del estándar:

  • Fondo bg-white, ícono text-[#6E7477], hover text-[#8936AB] (morado IIEG).
  • Tamaño w-7 h-7 en mobile, w-6 h-6 en desktop. Ícono w-3.5 h-3.5 / w-3 h-3 respectivamente.
  • Posición fixed bottom-4 right-4 z-50. Ajustable según contexto del huésped.
  • Shadow sutil shadow-[0px_2px_4px_0px_rgba(0,0,0,0.10)] que matchea el lenguaje visual del ecosistema IIEG.
  • Llama window.colibri.identify() con datos del usuario logueado y setContext('sourceRoute', ...) con la ruta actual antes de abrir el panel.

Variables de entorno necesarias (en .env.production o equivalente): 

VITE_COLIBRI_SOURCE_APP=mi-app
VITE_COLIBRI_API_KEY=ck_pub_TU_KEY

Montaje: en el componente Layout autenticado (después de ProtectedRoute), agrega <ColibriReportButton /> como hermano del <Outlet /> o equivalente. Solo aparece tras login y en cualquier ruta interna.

Proxy en dev (Vite): agrega /colibri y /api/public al proxy del vite.config.js apuntando al host de mariachi.

Script del bundle en index.html: 

<script src="/colibri/widget/colibri-widget.v1.js" defer></script>
Implementaciones de referencia: mapalab (frontend/src/components/ReportButton.jsx) y sieej (frontend/src/components/ColibriReportButton.jsx) usan exactamente este patrón.
Trampa común: el atributo style={{ padding: 0, border: 0 }} es necesario porque algunos huéspedes (incluyendo SIEEJ) tienen un reset CSS global tipo button { padding: 0.6em 1.2em; border: 1px solid } en su index.css. Esos selectores de tipo pueden ganar specificity sobre las utilities Tailwind y deformar el FAB en píldora. Inline style siempre gana — incluirlo evita el bug.

SDK para Node / server-side

Si necesitas reportar programáticamente desde un cron, Lambda, worker o cualquier proceso server-side, usa el SDK npm en lugar del widget.

npm install @iieg/colibri-sdk
import { Colibri } from '@iieg/colibri-sdk';

const colibri = new Colibri({
    sourceApp: 'mi-cron',
    apiKey: process.env.COLIBRI_API_KEY,
});

await colibri.report({
    tipo: 'bug',
    mensaje: 'Cron job falló en step 3',
    context: { jobId: 'abc-123' }
});
